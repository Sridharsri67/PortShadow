# 🛠️ Troubleshooting & Debugging Guide — PortShadow

This guide provides step-by-step diagnostic workflows for debugging test failures, port conflicts, WebSocket connections, and incarnation isolation validation errors.

---

## 1. Diagnostic Quick Reference

| Issue / Error Symptom | Likely Cause | Solution / Diagnostic Action |
|---|---|---|
| `EADDRINUSE: address already in use :::5000` | Port `5000` occupied by macOS AirPlay Receiver | Change `PORT` in `server/.env` to `5005` and `VITE_API_URL` in `client/.env` to `http://localhost:5005`. |
| `vitest: command not found` | Vitest binary missing in root workspace bin | Run `npm install -D vitest` at project root. |
| `Active connection already exists for tuple` | Attempted to create connection on active 4-tuple without closing previous connection | Call `ConnectionManager.closeConnection(id)` before creating new connection on identical 4-tuple. |
| `STALE_INCARNATION` | Packet generated by closed connection arrived at reused endpoint | Expected behavior! Verify that `packet.incarnationId !== activeConnection.incarnationId`. |
| CORS Origin Blocked in Client | `CLIENT_URL` mismatch between `server/.env` and Vite dev server | Set `CLIENT_URL=http://localhost:5173` in `server/.env`. |

## 3. Diagnosing Port Conflicts (e.g. macOS AirPlay Receiver)

On macOS Monterey, Ventura, Sonoma, and Sequoia, port `5000` is reserved by default by AirPlay Receiver.

### Symptoms
```text
Error: listen EADDRINUSE: address already in use :::5000
```

### Fix
1. Ensure `server/.env` contains:
   ```env
   PORT=5005
   CLIENT_URL=http://localhost:5173
   NODE_ENV=development
   ```
2. Ensure `client/.env` contains:
   ```env
   VITE_API_URL=http://localhost:5005
   VITE_PORT=5173
   ```
3. Ensure `client/vite.config.js` proxy targets `http://localhost:5005`.

## 5. Diagnostic Workflow: Verifying Incarnation Isolation

To verify that delayed packet isolation is functioning properly:

1. Create Connection A (`POST /api/connections` with `connectionId: "conn-A"`).
2. Generate Packet A1 (`POST /api/packets` with `packetId: "A1"`).
3. Generate Packet A2 & delay it (`POST /api/network/transmit` with `packetId: "A2"`, `delayMs: 5000`).
4. Close Connection A (`POST /api/connections/conn-A/close`).
5. Create Connection B on the exact same 4-tuple (`POST /api/connections` with `connectionId: "conn-B"`).
6. Release Packet A2 (`POST /api/network/release/A2`).
7. Verify rejection: Packet A2 status should transition to `REJECTED` with `rejectionReason: "STALE_INCARNATION"`.
